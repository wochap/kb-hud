# kb-hud

https://github.com/user-attachments/assets/43f146ce-df2c-4957-9b89-e7132d8b0868

kb-hud is a transparent desktop overlay for compatible ZMK keyboards. It
renders the keyboard from a keymap-drawer SVG and updates it in real time from
firmware telemetry received over Bluetooth LE.

The overlay shows pressed keys, active layers, transparent-key resolution,
effective modifiers, and available keyboard status such as endpoint, battery,
split connection, sequence gaps, and dropped notifications. Profiles select a
keyboard, SVG, scale, and visible status fields. A mock telemetry panel supports
UI development without keyboard hardware.

kb-hud is built with Tauri 2 and React 19. BLE support currently targets Linux
with BlueZ.

## Compatibility

The keyboard firmware must include
[`zmk-key-telemetry`](https://github.com/wochap/zmk-key-telemetry) and expose its
encrypted read/notify GATT service. Follow that module's documentation for its
ZMK, Zephyr, and firmware-build requirements. kb-hud does not depend directly
on a particular ZMK or Zephyr release; its external contract is the module's
telemetry protocol.

kb-hud requires the authoritative 48-byte telemetry state frame. It validates
the complete frame, requires the initial characteristic read to be a snapshot,
and does not guess or partially apply incompatible data. A notification needs
an ATT MTU of at least 51: 48 bytes of value plus the 3-byte ATT notification
header. The firmware must provide enough local L2CAP capacity and the BLE
connection must negotiate that MTU.

Telemetry represents at most 64 zero-based physical key positions and 32
layers. Position numbers and layer order must match the supplied SVG. Split
keyboards expose telemetry from the central half; the peripheral's key events
reach it through normal ZMK split processing. Optional status is displayed only
when its telemetry validity bit is set, so unavailable split, battery, endpoint,
or HID-indicator data may be omitted safely.

Shifted tap-label previews use US keyboard symbol mappings. The battery badges
label the central half `L` and the peripheral half `R`, so those labels assume a
left-central split; this does not affect key-position rendering or telemetry
transport.

The keyboard must already be paired with the host. The service UUID is not
advertised, so kb-hud connects to the selected paired device and performs GATT
discovery. The settings window lists paired devices and stores the selected MAC
in the active profile. Reconnection uses exponential backoff after sleep or
loss of signal. The `auto` profile value is a legacy alias match, not generic
service-based discovery; select an explicit device for other keyboard names.

## Keymap SVG

Provide an SVG generated by
[`keymap-drawer`](https://github.com/caksoylar/keymap-drawer) with its structural
classes preserved. kb-hud expects:

- one `g.layer-*` group per layer, in firmware layer-index order;
- the same physical positions on every layer;
- keys represented by `g.key.keypos-N` with a direct `rect.key` child; and
- tap and hold labels in `text.tap` and `text.hold` elements.

Transparent keys may use keymap-drawer's `trans` class or the `▽` tap label.
Every `keypos-N` must use the same zero-based physical position number emitted
by the firmware. Geometry is read from the SVG, so compatible split layouts are
not restricted to a particular shape or key count within the telemetry limits.

## Configuration

Open the settings window from the tray to configure profiles and exercise the
mock telemetry controls. Each profile contains:

- `name`
- `svgPath`
- `deviceMac` (an explicit Bluetooth MAC, or the limited `"auto"` mode described
  above)
- `scale`
- `hud` visibility flags

Profiles are stored in
`~/.config/com.wochap.kb-hud/profiles.json`, the Tauri configuration directory.
Changing the active profile updates the overlay immediately.

The tray icon requires a StatusNotifier host, such as a desktop panel with SNI
support. Its absence does not affect the overlay or settings windows.

## Build and development

Nix with flakes is required. The development shell provides Bun, Rust, and the
Tauri Linux dependencies.

```sh
nix develop
bun install
bun run tauri dev
```

Run the checks with:

```sh
bun run test
bun run build
cargo fmt --check --manifest-path src-tauri/Cargo.toml
cargo test --manifest-path src-tauri/Cargo.toml
```

Live BLE requires access to the host's Bluetooth controller and system BlueZ
D-Bus. It does not work in a container without those host resources; use the
mock telemetry panel for frontend work in that environment.

## Packaging

The Nix flake builds the frontend with
[`bun2nix`](https://github.com/nix-community/bun2nix) and the Tauri backend with
`buildRustPackage`:

```sh
nix build        # result/bin/kb-hud
nix run
```

Frontend dependencies are pinned in `bun.nix`. After changing `package.json`,
update the lockfile and generated Nix dependency set:

```sh
bun install
bunx bun2nix -o bun.nix
```

## Hyprland

The overlay window has class `kb-hud` and title `kb-hud overlay`. Use Hyprland
window rules to float, pin, position, and prevent focus for that window. kb-hud
does not control compositor placement or visibility; a show/hide binding can
move the window to and from a special workspace.
